# 为什么这样选证据？

> WHY 深课。分支对照表仍看 [04](04_分支怎么选.md)；英文决策树 [`../REVIEWS.md`](../REVIEWS.md) · [`../ROADMAP.md`](../ROADMAP.md)。  
> **只引用综述结论，不往仓库塞 PDF。**

## 1. 证据 → 方法（Ji / Freedman）

Ji *NRG* 2026：手里有什么信息（RNA、近缘参考、蛋白），就该选什么流水线。  
Freedman & Sackton *Genome Research* 2025：12 方法 × 21 物种的比较基准 — **TOGA、BRAKER3、StringTie** 常居前列；有 RNA 时证据路线显著更稳。

所以本仓不是「永远 BRAKER」或「永远 Helixer」，而是：

```text
近缘好参考 + 可投影     → S11（先 lift）
RNA + 蛋白，无近缘参考 → S1（BRAKER + StringTie 对照）
几乎只有蛋白           → S2
深 Iso-seq             → S3
GPU / 薄证据           → S13（对照，不偷换）
```

**反例：** 有近缘整理好的 GFF，却为了「显得原创」从零跑 Helixer 当主稿 — 浪费证据，还引入过召。

## 2. 为什么近缘参考时 S11 先于 de novo？

投影（Liftoff / LiftOn / CAT / ± TOGA）把**已经打磨过的模型**搬到新组装上，通常更快、更稳，并能抓住拷贝数变化带来的额外拷贝（Ji 2026）。  
空洞再用 S1/S2 补 — 不是「只 lift 就算完」。

前提：**参考真近、GFF 可信**。科级过远硬 lift → 系统性错模型。

**反例：** 用远缘模式植物 GFF 硬投影到目标，BUSCO 好看但局部基因座全错 — 仍应改走 S1。

## 3. 为什么有 RNA 时 StringTie 要和 S1 对照？

BRAKER 擅长证据引导的 CDS 模型；StringTie→TransDecoder 从转录重建 ORF，更敏感于 **isoform / UTR / 新转录结构**。  
Freedman 基准与 Ji 工作流都把转录重建放在「有 RNA」路径上。本仓要求：**对照轨，不是静默覆盖 BRAKER**。

**反例：** 只交 StringTie ORF 当「基因组注释终稿」，却不写 ab initio/证据训练路径 — 误差模式不同，审稿无法比较。

## 4. 为什么 S13 ≠ 静默的 S1？

Helixer / Tiberius / ANNEVO 等是 **GPU ab initio / 薄证据对照**（Nat Methods 2025–2026 一系）。  
有 RNA+蛋白时，EVALUATION 规定：用 S13 **顶替** S1 且不声明 → **自动不合格**。

原因：

1. 误差模式不同（过召短外显子 vs 证据不足漏检）；  
2. 综述与基准并未把它们定为「有 RNA 时的默认主引擎」；  
3. 对照轨的价值是找冲突，不是换牌子。

**反例：** METHODS 写「BRAKER3 annotation」，实际只提交 Helixer GFF。
