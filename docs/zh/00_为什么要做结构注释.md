# 为什么要做结构注释？

> 本课只讲 **WHY**。怎么跑、怎么验收 → [03](03_怎么开始跑.md) · [11](11_验收L0L1L2.md) · 英文 [`../EVALUATION.md`](../EVALUATION.md) / [`../ROADMAP.md`](../ROADMAP.md)。

## 结构注释是一层，不是「顺手一报」

基因组组装回答「碱基排成什么样」。  
**结构注释**回答另一层问题：**基因模型画在哪些坐标上**（gene / mRNA / exon / CDS）。

没有这一层：

- 你没有可复现的基因座 ID；
- 没有稳定的 `proteins.faa` 给质控与功能注释；
- 下游比较基因组、QTL、表达矩阵都会对不上账。

Ji *Nat Rev Genet* 2026 把结构与功能写成**两层**：先有模型，再谈同源命名与结构域。本仓库只负责第一层。

## 跳过结构（或只贴「预测结果」）的代价

| 跳过什么 | 常见后果 |
|----------|----------|
| 不写草稿支 ID / 工具版本 | METHODS 不可复现；审稿无法复盘 |
| 不做 soft-mask / 乱用 TE 库 | 假基因爆炸，或真基因（如 NLR）被抹掉 |
| 不跑蛋白 BUSCO + 分诊 | 「看起来有 GFF」≠ 完整基因集 |
| 直接拿 AI ab initio 当终稿 | 过召短外显子；有 RNA 时本该走证据路线 |
| 结构未过关就跑功能 | 给 TE ORF / 塌缩串联贴满 GO — 更糟 |

代价不是「少一张表」，而是**整条下游科学叙事建立在错误坐标上**。

## 预测 ≠ 注释（Yandell & Ence 2012）

经典区分（仍成立）：

| | 预测 (prediction) | 注释 (annotation) |
|--|-------------------|-------------------|
| 是什么 | 算法在基因组上画出可能的基因 | 带证据、版本、QC、可放行的基因集 |
| 产出感 | 「跑出了一个 GFF」 | 「这套模型通过门禁，可写 METHODS」 |
| 失败模式 | 分数好看但错位点多 | 诚实标 L0 / 暂缓，而不是假装终稿 |

本 playbook 的草稿支（S1/S11/…）是**有证据选择的预测流水线**；L0→L1→L2 才是注释等级。  
**反例：** 把 Helixer 一次输出直接写成「我们完成了基因组注释」——那是预测快照，不是合格注释。

## 结构 ≠ 功能（Ji *NRG* 2026）

| 层 | 问题 | 产物 | 仓库 |
|----|------|------|------|
| **结构** | 基因在哪？ | GFF + proteins | **本仓** |
| **功能** | 蛋白像什么？ | master TSV（GO/域/名） | [功能仓](https://github.com/Xuzhen-Li/gene-function-annotation) |

功能层**不能**修复错误外显子、TE 假基因或串联塌缩。  
**反例：** Swiss-Prot 命中很漂亮，但坐标落在重复区 ORF 上 — 功能表在装饰坏模型。
